## Stack triggers 文件研究

讀 [官方文件](https://terramate.io/docs/how-to/change-detection/stack-triggers)，重點：

- `terramate trigger --change <stack-path>` 產出 `.tmtriggers/<stack>/changed-<uuid>.tm.hcl`
- `.tmtriggers/` 必須 commit（不能 gitignore）
- 觸發後 change detection 把 stack 視為 changed，CI `terramate run --changed` 會跑

## 學到的事

### 1. `terramate trigger` 是 PR-first 流程下處理 CI apply 失敗的正解

- 比 `gh run rerun --failed` 可靠（不受 main 移動影響）
- 比本地 manual apply 乾淨（保留 PR 審計軌跡）
- trigger 檔本身是 commit-able 的 HCL，符合 IaC 哲學

### 2. CLI flag 細節：`--change` 不是 default

`terramate trigger <stack>` 沒有 `--change` 會走 default 行為。要強制 changed 必須顯式 `--change`，另有 `--ignore-change` 反向。第一次用容易忽略。

### 3. Runbook 該放哪：labs/ vs docs/runbooks/

- `labs/`：學習路徑、單次走完
- `docs/runbooks/`：事件手冊、重複查閱

兩者讀者意圖不同，分目錄。今天開了 `docs/runbooks/`，後續類似性質文件（如 drift recovery、state corruption）都放這。

#### 踩坑一：CodeQL 拒收多 SARIF 同 category

PR #25 CI plan ✅、Trivy 掃描本身 ✅（只 LOW/MEDIUM，pre-existing VPC flow logs），但 **SARIF upload fail**：

```
The CodeQL Action does not support uploading multiple SARIF runs
with the same category.
```

GitHub 2025-07-21 policy change。本 PR 同時改 dev/gke + dev/network（globals 搬家）→ 兩 SARIF → 撞牆。未修則未來任何 multi-stack PR 都會卡。

修法 [PR #26](https://github.com/fengnux/tofu-terramate-lab/pull/26)：`.github/workflows/opentofu.yml` 的 `jq` merge 改 flatten 多 run 為單一 run、rules 依 id 去重。

**Codex review 抓 bug**：第一版 jq `.[0].runs[0].tool.driver | .rules = ([.[].runs[].tool.driver.rules ...])`，pipe 後 `.` 已變成第一個 driver object，`.[]` 解不到原 array → 本地用兩份 minimal SARIF 重現 `jq: error: Cannot index string with string "runs"`。修法用 `. as $docs` 保存原 array。

驗證：把 PR #25 暫時 merge 進 fix-sarif branch（真實 multi-stack 場景）跑 CI → Trivy upload ✅。確認在實戰有效後才 merge PR #26。

## 學到的事

### 1. Stack trigger 是 PR-first 流程下處理「code 沒改但要重 apply」的正解

比 rerun 可靠（不受 main 移動影響）、比 manual apply 留審計軌跡。`--change` flag 必須顯式。

### 2. Runbook 設計階段除了 IAM permission，還要列「資源 → 必啟 API」

兩次都是 lab 開跑後撞錯才發現（dev/vm 缺 SA admin、dev/gke 缺 container API）。未來 lab template 增加「prereq matrix」section：每個新 resource type 對應檢視 IAM role + GCP API。

### 3. Multi-stack PR 必踩 GitHub CodeQL 新 policy（2025-07）

跟程式碼安全性無關的 CI 工程 bug。已 generalized 修在 workflow，未來不會再撞。

### 4. Codex review 抓到我 jq 寫的 scoping bug

第一版 fix 在 pipe 後 `.` 失去原 array context，`.[].runs[]` 解到 string 上炸 jq error。教訓：jq 多層 pipe + 同時 mutate 中間值時，用 `. as $var` 顯式保存原輸入，比依賴隱式 `.` 安全。Codex 提的修法本地兩份 minimal SARIF 一試就重現原錯、驗證新版正確 → 合作流程順。

### 5. Workload Identity 不只是「不放 key」，還是 K8s ↔ GCP 邊界的稽核錨點

GSA log 看 metadata server 換 token 的 caller，能對回到 K8s namespace/KSA。傳統 JSON key mount 模式裡這條軌跡是斷的。

### 6. dev-vm SA 最小權限與「demo script 一站式」有衝突

lab 簡化希望全程 dev-vm 跑，但最小權限 SA 跑不到 IAM admin。實作上分兩端執行更乾淨，也更貼近 production（IaC 管 GCP-side、kubectl 管 K8s-side）。

### 7. Autopilot 計費紀律：~9 min create + ~6 min destroy = 一次跑 ~15min 對 control plane 計時

regional control plane 是按時計費（~$0.10/hour 等級），實驗區間越短越好。Phase G 不是禮貌、是預算硬要求。
