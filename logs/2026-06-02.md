### Phase 1–5 — evidence GCS bucket（PR #30）

新增 `stacks/evidence/storage/` 4 個手寫檔 + 4 個 generated。Plan = +2（bucket + iam_member）。

設計上的兩個小決策（路上發現）：

- **`bucket_name` 不走 globals 注入**：lab runbook 原本要從 globals 橋接 `bucket_name` 進 `_locals.tf`，但 `${data.google_client_config.current.project}-evidence` 內聯更短且符合既有 WIF stack 慣例。最後 `_locals.tf` 只剩 `personal_email` 一個 entry

## 學到的事

### 1. 「reader binding 不依賴 Owner」的論點只覆蓋讀的一半

ADR-003 §3.1 原本只說「明寫 reader binding 顯化讀取者意圖、不依賴 project Owner」。Codex review 戳破：寫測試仍依賴 Owner。這條經驗是設計 IAM 時要**逐動作**檢查能力源頭，不能假設「寫了一條 binding 就把獨立性都建好了」。

### 2. Lab runbook 的 `locals.tm.hcl` 命名是誤導

runbook 用「`locals.tm.hcl`」描述 globals 注入機制，但 Terramate 實際慣例是用 `generate.tm.hcl` 寫 `generate_hcl` block 產出 `_*.tf`。實作時應該以既有 stack（dev/network）的真實 pattern 為準，不是照 runbook 字面複製檔名。

### 3. Terramate git safeguard 的規則更新

session 中與 user 重新校準：safeguard 不是「禁止繞過」而是「有理由才繞過」。最初的禁止規則是因為當時繞過理由不足，被誤推廣成永久規則。Memory 已更新 ([feedback_no_disable_safeguards.md](../../.claude/projects/-Users-fengnux-GitHub-research/memory/feedback_no_disable_safeguards.md))。

### 4. ADR-003 在這次跑出 3 個補丁，但都收斂在同一份文件

3.1 不依賴 Owner、4.1 stack 路徑、§3 CMEK production path、觀察指標 +2 條。一次 lab 反過來把 ADR 補完是好事 —— 顯示原 ADR 雖然方向對，但「為什麼選 A 不選 B」深度不夠，實作時會冒出來。下次寫 ADR 可以先預想實作者會問什麼。
