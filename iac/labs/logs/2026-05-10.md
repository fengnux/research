## 重要釐清

### tenv 版本切換 vs OpenTofu 版本鎖定

| 機制 | 檔案 | 作用 |
|------|------|------|
| tenv 版本切換 | `.opentofu-version`、`.terramate-version` | 告訴 tenv 在此目錄使用哪個版本的 CLI |
| OpenTofu 版本鎖定 | `versions.tf` 的 `required_version` | OpenTofu 本身強制執行，版本不符則中止 |
| Provider 版本鎖定 | `.terraform.lock.hcl` | 鎖定 provider 確切版本，確保可重現 |

### gcloud 預設 project vs OpenTofu target project

`gcloud config set project` 與 OpenTofu 的操作目標無關。
OpenTofu 使用 ADC 憑證，target project 由 provider 區塊中的 `project` 決定。
因此本機 gcloud 預設為主要專案（`fengnux-1168`），OpenTofu 仍可操作 `research-lab-495809`。

### Project ID 命名陷阱

GCP project ID 全球唯一。建立時若名稱被佔用，console 會自動加數字後綴（例如 `research-lab` → `research-lab-495809`）。後續所有設定（globals、bucket 名稱）都要用實際 ID，不能用顯示名稱。

### Terramate `tm_` 前綴函數

`generate_hcl` 內：
- 不加前綴的函數（例如 `replace()`）會原封不動寫進產生檔，由 Terraform/OpenTofu 在 runtime 評估
- 加 `tm_` 前綴（例如 `tm_replace()`）由 Terramate 在 generate 階段直接評估，產生靜態值

實作 default labels 時最初寫 `replace(...)` 導致生成檔含原始函數呼叫，改 `tm_replace(...)` 後正確輸出靜態字串。

### Terramate working tree 檢查

`terramate run` 預設拒絕在 git working tree 髒（uncommitted/untracked）時執行，避免狀態漂移。
Provider 升級這類臨時操作可加 `--disable-check-git-untracked --disable-check-git-uncommitted` 暫時繞過，但事後務必 commit。
