## 踩坑

### 坑一：IAM propagation（首次 `workflow_dispatch`）

第一次觸發立即 403：`Permission 'iam.serviceAccounts.getAccessToken' denied`。

原因：WIF IAM binding 剛 apply 完不到幾分鐘，GCP IAM 尚未全球同步。

解法：重新觸發即可（第二次成功通過 auth）。

### 坑二：provider download timeout（第二次觸發）

第一次 IAM 問題消失後，改成 provider 下載 timeout：
```
net/http: request canceled (Client.Timeout exceeded while awaiting headers)
```

原因：drift job 同時對所有 stack 跑 `tofu init`，下載 google provider SHA256SUMS 時 github.com 連線逾時。PR plan job 只對 changed stacks 跑，通常只有 1 個 stack，比較不容易觸發。

解法：加 `actions/cache@v4` + `TF_PLUGIN_CACHE_DIR` 快取 provider 二進位。

commit [be36913](https://github.com/fengnux/tofu-terramate-lab/commit/be36913)

### 坑三：`TF_PLUGIN_CACHE_DIR: ~/.terraform.d/plugin-cache` 字面 `~`

加了 plugin cache 後，下一次觸發在 Drift check 步驟報 `Error: repository has untracked files`。

根本原因：YAML `env` block 的值不經 shell 展開，`~` 是字面值。OpenTofu 用 Go 的 `os.MkdirAll` 建立 `~/` 時，把 `~` 當相對路徑，在各 stack 目錄下建了 `~/` 資料夾——不在 `.gitignore` 裡，Terramate git safeguard 直接 fail。

解法：從 `env` block 移除 `TF_PLUGIN_CACHE_DIR`，改在 "Create plugin cache dir" step 透過 `GITHUB_ENV` 設定：
```bash
echo "TF_PLUGIN_CACHE_DIR=$HOME/.terraform.d/plugin-cache" >> "$GITHUB_ENV"
```

commit [f84da3f](https://github.com/fengnux/tofu-terramate-lab/commit/f84da3f)

### 坑四：`--label drift` label 不存在

第三次觸發時 drift check 通過（有偵測到東西），但 `gh issue create --label drift` 失敗：
```
could not add label: 'drift' not found
```

解法：issue 建立前先用 `gh label create ... 2>/dev/null || true` 確保 label 存在。

commit [afb0933](https://github.com/fengnux/tofu-terramate-lab/commit/afb0933)

### 坑五：舊 drift check 實作 exit code 被 printf 蓋掉

run 25977776828 顯示「無 drift、全綠」，但 dev/vm 實際上有 drift（VM 已 destroy，config 仍定義 VM）。

根本原因：舊實作用 `sh -c '... && tofu plan -detailed-exitcode; printf "\`\`\`"'`，`sh -c` 的 exit code 是最後一個指令 `printf`（exit 0），把 `tofu plan` 的 exit 2 完全蓋掉。`terramate run` 因此看到 exit 0，drift step 標記 success，issue 從未建立。

解法：放棄 `terramate run` 包法，改為手動 `while` 迴圈逐 stack 執行，用 `|| plan_exit=$?` 明確捕捉 exit code：

```bash
plan_exit=0
(cd "$GITHUB_WORKSPACE/$stack" && tofu plan -detailed-exitcode ...) >> "$report" 2>&1 || plan_exit=$?
case $plan_exit in
  0) ;;
  2) drift_found=true ;;
  *) error_found=true ;;
esac
```

同時拆成兩個 output：`drift_found`（exit 2）和 `error_found`（exit 1），後續 steps 分別用 `steps.drift.outputs.drift_found == 'true'` 和 `steps.drift.outputs.error_found == 'true'` 判斷。

commits：[6f01789](https://github.com/fengnux/tofu-terramate-lab/commit/6f01789)、[656eed0](https://github.com/fengnux/tofu-terramate-lab/commit/656eed0)

### 坑六：`set -e` 與 exit 2 提前退出

改用 `||` 模式後第一次跑，drift check step 以 exit 2 結束，後續 steps 全被跳過（issue 未建立）。

原因：GitHub Actions bash 預設 `set -e`；`(subshell)` 回傳 2 時，即使下一行是 `plan_exit=$?`，bash 已在賦值前退出。加上 `|| plan_exit=$?` 讓 `||` 右側吸收 non-zero exit，`set -e` 不再觸發。

## 學到的事

### 1. Trivy 供應鏈攻擊事件影響使用模式

2026-03 trivy-action 76 個 tag 被 force-push、setup-trivy 全 tag 竄改、trivy v0.69.4-6 為惡意版本。**緩解措施**：所有 action 用 commit SHA 而非 tag、不依賴中間 action wrapper、直接 install + SHA pin binary。

### 2. trivy config 與 trivy image 是不同 sub-command

- `trivy config`：IaC misconfig 掃描，不支援 `--ignore-unfixed`（fix PR 才發現）
- `trivy image`：CVE 漏洞掃描，`--ignore-unfixed` 在這裡才有意義（不顯示無修補版的 CVE）

### 3. Trivy 嚴重度分級有自己的觀點

「Firewall 開 SSH 給 0.0.0.0/0」在很多 audit framework 是 HIGH，但 Trivy 是 **MEDIUM**。如果要把這類規則升級為 fail，需要自己加 `--severity LOW,MEDIUM,HIGH,CRITICAL` 並用 `.trivyignore` 把可接受的 MEDIUM 排除。

### 4. Code Scanning UI 預設 filter 是 `branch:main`

PR scan 產生的 alert 在 `refs/pull/N/merge` ref，不會出現在 main filter。要看 PR alert：搜尋框輸入 `pr:N`，或從 PR conversation/Files Changed tab 進入。PR closed 不 merge 後 alert 自動 dismiss。

### 5. PR-first workflow 正式落地

本 lab 起所有 stack/workflow 變更走 PR：feature branch → CI plan + scan → review → merge → CI apply。Foundational stack 還是本機 apply 但 .tf 也走 PR。記入 memory `feedback_pr_first_workflow.md`。
