## 踩坑

### 坑一：IAM propagation（首次 `workflow_dispatch`）

第一次觸發立即 403：`Permission 'iam.serviceAccounts.getAccessToken' denied`。

原因：WIF IAM binding 剛 apply 完不到幾分鐘，GCP IAM 尚未全球同步。

解法：重新觸發即可（第二次成功通過 auth）。

### 坑二：provider download timeout（第二次觸發）

第一次 IAM 問題消失後，改成 provider 下載 timeout：
```
net/http: request canceled (Client.Timeout exceeded while awaiting headers)
```

原因：drift job 同時對所有 stack 跑 `tofu init`，下載 google provider SHA256SUMS 時 github.com 連線逾時。PR plan job 只對 changed stacks 跑，通常只有 1 個 stack，比較不容易觸發。

解法：加 `actions/cache@v4` + `TF_PLUGIN_CACHE_DIR` 快取 provider 二進位。

commit [be36913](https://github.com/fengnux/tofu-terramate-lab/commit/be36913)

### 坑三：`TF_PLUGIN_CACHE_DIR: ~/.terraform.d/plugin-cache` 字面 `~`

加了 plugin cache 後，下一次觸發在 Drift check 步驟報 `Error: repository has untracked files`。

根本原因：YAML `env` block 的值不經 shell 展開，`~` 是字面值。OpenTofu 用 Go 的 `os.MkdirAll` 建立 `~/` 時，把 `~` 當相對路徑，在各 stack 目錄下建了 `~/` 資料夾——不在 `.gitignore` 裡，Terramate git safeguard 直接 fail。

解法：從 `env` block 移除 `TF_PLUGIN_CACHE_DIR`，改在 "Create plugin cache dir" step 透過 `GITHUB_ENV` 設定：
```bash
echo "TF_PLUGIN_CACHE_DIR=$HOME/.terraform.d/plugin-cache" >> "$GITHUB_ENV"
```

commit [f84da3f](https://github.com/fengnux/tofu-terramate-lab/commit/f84da3f)

### 坑四：`--label drift` label 不存在

第三次觸發時 drift check 通過（有偵測到東西），但 `gh issue create --label drift` 失敗：
```
could not add label: 'drift' not found
```

解法：issue 建立前先用 `gh label create ... 2>/dev/null || true` 確保 label 存在。

commit [afb0933](https://github.com/fengnux/tofu-terramate-lab/commit/afb0933)
