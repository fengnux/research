## 踩坑：`var.project_id` 在 `.tf` 裡無效

### 問題

Runbook 範例的 `main.tf` 使用 `var.project_id`，但 vm stack 沒有宣告這個 variable，plan 直接報錯：

```
Error: Reference to undeclared input variable
  on main.tf line 5: project = var.project_id
```

### 根因

Terramate globals（`global.gcp.lab_project`）只能在 `.tm.hcl` 檔裡讀取，不能在 `.tf` 裡直接引用。其他 stack（apis / network）不需要 project ID 是因為：

- `google_project_service` 只需要 `service`，`project` 由 provider 層的 `project = "research-lab-495809"` 接管
- network 資源（VPC / subnet / firewall / NAT）同樣靠 provider project，不需明確指定

vm 的 `network_interface.subnetwork` 需要完整路徑字串（`projects/<project>/regions/...`），因此需要在 `.tf` 層取到 project ID。

### 解法

在 vm stack 內新增 `locals.tm.hcl`，用 `generate_hcl` 把 globals 值橋接到 HCL locals：

```hcl
generate_hcl "_terramate_locals.tf" {
  content {
    locals {
      project_id = global.gcp.lab_project
    }
  }
}
```

`main.tf` 改用 `local.project_id`，`project` 欄位完全不填（交給 provider）。

### 慣例確立

> **`.tf` 需要 globals 值時，一律透過 `generate_hcl` 橋接，不使用 `variable` 宣告。**

這樣所有環境設定都集中在 `config.tm.hcl`，`.tf` 只管邏輯，不持有具體值。
