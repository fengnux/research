## 踩坑：`network_interface` 欄位誤用

### 問題一：`var.project_id` 在 `.tf` 裡無效

初版 `main.tf` 使用 `var.project_id`，但 vm stack 沒有宣告此 variable，plan 報錯：

```
Error: Reference to undeclared input variable
  on main.tf line 5: project = var.project_id
```

Terramate globals（`global.gcp.lab_project`）只能在 `.tm.hcl` 裡讀取，不能直接出現在 `.tf`。其他 stack 沒踩這個坑是因為 apis / network 的資源不需要在欄位裡填 project 字串。

### 問題二：subnetwork 不需要完整路徑

誤以為 `network_interface.subnetwork` 需要完整 self-link（`projects/<project>/regions/<region>/subnetworks/<name>`）。實際上 Google provider 文件說明：`network` 與 `subnetwork` 只需指定其中一個，若填 `subnetwork`，VPC 從子網路自動推導；名稱、partial URL、full self-link 三種格式都接受。Provider 已設定 `project` 和 `region`，直接用子網路名稱即可。

### 最終寫法

```hcl
network_interface {
  subnetwork = "dev-subnet-asia-east1"
  # access_config 不加 → 無 public IP
}
```

無需 `network`、無需完整路徑、無需 `local.project_id`。
