## Stack triggers 文件研究

讀 [官方文件](https://terramate.io/docs/how-to/change-detection/stack-triggers)，重點：

- `terramate trigger --change <stack-path>` 產出 `.tmtriggers/<stack>/changed-<uuid>.tm.hcl`
- `.tmtriggers/` 必須 commit（不能 gitignore）
- 觸發後 change detection 把 stack 視為 changed，CI `terramate run --changed` 會跑
- 觸發檔可隨時刪掉，不影響過去 run

## 學到的事

### 1. `terramate trigger` 是 PR-first 流程下處理 CI apply 失敗的正解

- 比 `gh run rerun --failed` 可靠（不受 main 移動影響）
- 比本地 manual apply 乾淨（保留 PR 審計軌跡）
- trigger 檔本身是 commit-able 的 HCL，符合 IaC 哲學

### 2. CLI flag 細節：`--change` 不是 default

`terramate trigger <stack>` 沒有 `--change` 會走 default 行為。要強制 changed 必須顯式 `--change`，另有 `--ignore-change` 反向。第一次用容易忽略。

### 3. Runbook 該放哪：labs/ vs docs/runbooks/

- `labs/`：學習路徑、單次走完
- `docs/runbooks/`：事件手冊、重複查閱

兩者讀者意圖不同，分目錄。今天開了 `docs/runbooks/`，後續類似性質文件（如 drift recovery、state corruption）都放這。
